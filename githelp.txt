# 🔄 Workflow для работы на двух машинах

## 🎯 Золотое правило (TL;DR)

```
🔴 ПЕРЕД уходом с машины → git add + commit + push
🟢 ПРИХОДЯ на машину    → git pull (с rebase)
```

Если будете следовать этому правилу — **никогда не будет проблем** с синхронизацией.

---

## ⚙️ Одноразовая настройка (выполнить на обеих машинах)

```bash
# Используем rebase вместо merge — история будет линейной и чистой
git config --global pull.rebase true

# Удобные алиасы (сокращения)
git config --global alias.s "status"
git config --global alias.c "commit -m"
git config --global alias.p "push"
git config --global alias.pl "pull"
git config --global alias.a "add -A"
git config --global alias.l "log --oneline --graph -20"

# Авто-настройка конца строк (чтобы Windows и Mac не ругались)
git config --global core.autocrlf true    # на Windows
git config --global core.autocrlf input   # на Mac
```

После этого можно использовать короткие команды:
```bash
git s      # вместо git status
git a      # вместо git add -A
git c "msg"  # вместо git commit -m "msg"
git p      # вместо git push
git pl     # вместо git pull
```

## 📋 Пошаговый workflow

### 🖥 Сценарий: Заканчиваете работу на Windows, уходите к MacBook

```bash
# 1. Проверили что ничего не забыли
git status

# 2. Добавили все изменения
git add -A

# 3. Закоммитили с понятным сообщением
git commit -m "feat: добавил функцию Х"

# 4. Запушили на GitHub
git push origin master

# ✅ Можно закрывать Windows
```

### 💻 Сценарий: Пришли на MacBook, продолжаете работу

```bash
# 1. Зашли в папку проекта
cd ~/Code/PelvicTrainer2

# 2. Подтянули последние изменения
git pull origin master

# 3. Работаете...

# 4. Перед уходом — снова коммит + push (см. выше)
```

## 🚨 Типичные проблемы и решения

### Проблема 1: "Забыл закоммитить на Windows, пришёл на Mac"

```bash
# На Mac увидите что ваша ветка отстала
git pull origin master

# Если Windows ещё работает — зайдите и запушьте
# Если Windows выключен — придётся либо ждать, либо работать на Mac без последних изменений
```

**Решение:**养成习惯 коммитить перед уходом. Даже с сообщением "wip" (work in progress).

### Проблема 2: "Работал на обеих машинах параллельно"

```bash
# Git покажет конфликты
git pull origin master

# IDE откроет визуальное сравнение:
# - Accept Theirs (версия с GitHub)
# - Accept Yours (ваша локальная версия)
# - Merge (объединить обе)
```

**Совет:** Никогда не работайте на двух машинах одновременно без коммитов. Это гарантированно приведёт к потере кода.

### Проблема 3: "Локальные изменения мешают pull"

```bash
# Вариант A: Временно спрятать изменения
git stash
git pull origin master
git stash pop

# Вариант B: Закоммитить "в процессе"
git add -A
git commit -m "wip: работаю над Y"
git pull origin master
```

### Проблема 4: "Случайно удалил/изменил файл"

```bash
# Восстановить файл из последнего коммита
git restore path/to/file

# Или через IDE: ПКМ на файле → Git → Rollback
```

## 🎨 Альтернатива: через IDE (Android Studio)

### На Windows (Android Studio):
1. **Commit окно** (`Ctrl+9`)
2. Выделите файлы → `Ctrl+Shift+A` → "Commit"
3. Введите сообщение → **Commit and Push**

### На Mac (Android Studio):
1. **Git → Update Project** (`Cmd+T`)
2. Выберите **Rebase** → OK
3. Работаете

### Перед уходом с Mac:
1. **Commit окно** (`Cmd+9`)
2. Commit and Push

## 📱 Шпаргалка команд для ежедневной работы

### Каждый день на обеих машинах:

```bash
# Утро (пришли на машину)
git pull origin master

# В процессе работы (часто)
git add -A
git commit -m "feat: добавил X"

# Вечер (уходите с машины)
git push origin master
```

### Раз в неделю:
```bash
# Посмотреть историю
git log --oneline --graph -20

# Удалить старые ветки
git branch -d old-branch
git push origin --delete old-branch

# Проверить что репозиторий чистый
git status
git gc  # оптимизировать хранилище
```

## 💡 Продвинутые советы

### 1. Используйте осмысленные сообщения коммитов
```
✅ feat: добавлен pull-to-refresh в календаре
✅ fix: исправлен баг с переносом текста в меню
✅ refactor: вынес EmptyState в переиспользуемый компонент

❌ fix
❌ update
❌ changes
```

### 2. Коммитьте часто, но логически завершёнными кусками
```
Плохо:  1 коммит на весь день работы
Хорошо: 5-10 коммитов за день (каждый — законченная фича)
```

### 3. Перед коммитом всегда делайте `git status`
Проверяйте что не коммитите случайно:
- `build/` папки
- `.idea/`
- `local.properties`
- Секретные ключи

### 4. Используйте .gitignore правильно
Добавьте всё что не нужно синхронизировать между машинами.
